# Thought for the day

The second line of every post. One italic line, product lens, a little witty, never sarcastic about a person or a team. It is the only line in the post that is not evidence, which is why it has rules.

## Rules

1. Start from Niel's working rules and reword them; add fresh lines in the same register when the seed set runs thin.
2. No line repeats within twenty working days. `scripts/run-context.mjs` lists the lines used in the last twenty logs under `recentThoughts`; pick one that is not there.
3. The same line goes to all five teams on a given day. It is a thought for the day, not a thought per team.
4. Record the line in the daily log as `Thought: "<line>"` so the rotation can be checked.
5. Never a line that reads as a comment on that day's incidents or on a named person. If the obvious line would land as a dig, pick another.
6. No quotes attributed to famous people. The voice is the house voice.

## Seed lines, in the register

The five from the runbook, then fifteen more in the same voice. Twenty is the rotation length, so a run can go a month before it needs a new one; write new lines rather than shortening the gap.

1. Done means released and used. Testing is a waiting room, not a destination.
2. An incident nobody owns is an incident everybody owns, which is nobody.
3. Close before you open.
4. A report nobody opens is a rumour.
5. Zero incidents is not luck, it is a habit.
6. Small and shipped beats big and nearly.
7. The venue does not care which sprint it was in.
8. A Friday night is the only test environment that counts.
9. If the fix is in Code Review, the customer still has the bug.
10. Three things in progress is a plan. Five is a queue.
11. The ticket is not the work. The change in the venue is the work.
12. A decision nobody wrote down was a conversation.
13. Unassigned is a status for furniture, not incidents.
14. Fast feedback is cheaper than a careful guess.
15. If it needs a workaround, it is not finished.
16. The oldest open incident is the one that says the most about us.
17. Ship the boring fix. Boring is what reliable looks like from the inside.
18. A date in Jira is a promise. A date in a chat is a hope.
19. Every day at zero is a day the product earned its keep.
20. Say what changed, not what you did.
